# MASTEREVA — Агрегатор прайс-листів для маркетплейсу EVA

Автоматична система що збирає товари від кількох постачальників, об'єднує їх в єдиний XML-прайс у форматі YML і публікує через GitHub Pages. EVA (eva.ua) підтягує цей файл автоматично кожні 4 години.

## Як це працює

```
Постачальники (XML/YML фіди)
        │
        ▼
GitHub Actions (запускається кожні 4 години)
        │
        ├─ завантажує XML від кожного постачальника
        ├─ перевіряє наявність, ціну, фото
        ├─ додає націнку
        ├─ об'єднує в один файл Masterevanew.xml
        ├─ зберігає REPORT.md і price_warnings.log
        │
        ▼
GitHub Pages (CDN)
        │
        ▼
EVA маркетплейс (отримує прайс за посиланням)
```

**Цикл оновлення:** скрипт запускається автоматично кожні **4 години** (cron `0 */4 * * *`). Також запускається при кожному push в `main` якщо змінились `.py`, `.xml` або `.html` файли. Можна запустити вручну через кнопку **"Run workflow"** у GitHub Actions.

## Конфігурація

Всі налаштування знаходяться на початку файлу `masterevaxml.py`.

### SOURCES — список постачальників

```python
SOURCES = [
    ("префікс_категорій", "https://url-фіду"),
    ...
]
```

- **Перший елемент** — рядковий префікс що додається до ID категорій (`"1111"` → категорія `"1111123"`)
- **Другий елемент** — URL XML/YML фіду постачальника
- Порожній префікс `""` — категорії без змін (kievopt)

### OFFER_ID_PREFIXES — префікси offer ID

```python
OFFER_ID_PREFIXES = {
    "домен.com": "1111",
}
```

Домени що є в цьому словнику отримують prefix + підкреслення перед своїм offer ID:
`"1111"` + `"_"` + `"ABC123"` = `"1111_ABC123"`

Домени **яких немає** в словнику (kievopt, royaltoys) — їх offer ID залишаються без змін.

### CUSTOM_MARKUP — індивідуальна націнка

```python
CUSTOM_MARKUP = {
    "домен.com": {
        "markup_percent": 1.15,   # 1.0 = 0%, 1.15 = +15%, 1.35 = +35%
        "markup_fixed":   30,     # фіксована надбавка в грн
        "min_price_raw":  70,     # (опц.) мінімум від ЦІНИ ПОСТАЧАЛЬНИКА до націнки
    },
}
```

Якщо постачальника **немає** в `CUSTOM_MARKUP` — використовується глобальна:
```python
MARKUP_PERCENT = 1.35   # +35%
MARKUP_FIXED   = 40     # +40 грн
```

**Формула ціни:**
```
final_price = round(supplier_price_uah × markup_percent + markup_fixed)
old_price   = round(final_price × 1.25)
```

### Інші константи

| Константа | За замовч. | Опис |
|---|---|---|
| `MIN_PRICE_THRESHOLD` | 199 | Мінімальна ціна в грн (після націнки) |
| `MIN_OFFERS_PER_CATEGORY` | 3 | Категорії з ≤ N товарів видаляються |
| `DESC_LIMIT` | 2800 | Максимальна довжина опису (символів) |
| `DEFAULT_QTY` | 2 | Кількість якщо постачальник не вказав |
| `REQUEST_DELAY` | 3 | Пауза між запитами до постачальників (секунди) |
| `MAX_PRICE_UAH` | 500 000 | Максимальна ціна — захист від помилок |
| `SUSPICIOUS_LOW_UAH` | 10 | Підозріло низька ціна — захист від помилок |
| `OLD_PRICE_MULT` | 1.25 | Множник для ціни "до знижки" |

## Повний опис пайплайну

Скрипт виконує **10 кроків** при кожному запуску:

### Крок 0 — Актуальні курси НБУ
Робить один запит до НБУ API (`bank.gov.ua`) і отримує поточні курси USD, EUR та інших валют. При помилці — використовує захардкоджені резервні курси з `FALLBACK_RATES`.

### Крок 1 — Завантаження blacklist
Читає файл `blacklist.txt`. Якщо файл відсутній — продовжує без нього.

### Крок 2 — Завантаження фідів
Для кожного постачальника:
- Завантажує XML/YML файл з timeout 120 секунд
- **3 спроби** при помилці (пауза 15 сек між спробами)
- Перевіряє Content-Type (захист від HTML-сторінки замість XML)
- Розпаровує XML через `lxml` з `recover=True` (обробляє "брудний" XML)
- Отримує курси валют із секції `<currencies>` фіду

### Крок 3 — Збір offer ID (прохід 1)
Перший прохід по всіх товарах для виявлення дублікатів **без** повної обробки. Визначає:
- Дублікати між різними постачальниками
- Дублікати всередині одного постачальника

### Крок 4 — Обробка категорій
- Додає префікс до ID кожної категорії та до `parentId`
- Вирішує колізії ID (якщо два постачальники мають однаковий ID після префіксації)
- Нормалізує назви категорій (HTML entities, спецсимволи)

### Крок 5 — Обробка товарів (прохід 2)
Для кожного товару послідовно:
1. **Blacklist** — пропускаємо якщо offer ID в списку
2. **Дублікати** — пропускаємо якщо є конфлікт ID
3. **Наявність** — перевіряємо `available`, `in_stock` (атрибут або тег)
4. **Ціна** — парсимо, конвертуємо у гривні, застосовуємо націнку
5. **Мінімальна ціна** — перевіряємо поріг
6. **Назва** — читаємо `name_ua` → `name`, мінімум 3 символи
7. **Опис** — очищуємо від `<script>`, `<style>`, `<iframe>`, `<video>`, `<audio>`, `<img>`, URL, коментарів; захист CDATA від `]]>`
8. **Фото** — валідуємо URL (тільки http/https), дедублікуємо, максимум 15
9. **Параметри** — зчитуємо, обмежуємо name 100 символів, value 255 символів
10. **Стоки** — `min(qty, 9999)`, якщо немає — `DEFAULT_QTY`

### Крок 6 — Валідація categoryId
Видаляємо товари що посилаються на неіснуючу категорію.

### Крок 6.5 — Видалення тонких категорій
- Підраховуємо прямі товари для кожної категорії
- Видаляємо категорії з ≤ `MIN_OFFERS_PER_CATEGORY` товарів
- **Батьківські категорії НЕ видаляються** (навіть якщо мають 0 прямих товарів) — щоб не зламати ієрархію

### Крок 7 — Збірка XML
Генерує `Masterevanew.xml` у форматі YML з DOCTYPE.

### Крок 8 — Логи
Зберігає `price_warnings.log` з усіма попередженнями.

### Крок 9 — REPORT.md
Генерує детальний звіт у Markdown.

### Крок 10 — Консольний вивід
Виводить підсумок у лог GitHub Actions.

## Як додати постачальника

Потрібно змінити **до 3 місць** у `masterevaxml.py`:

### 1. SOURCES (обов'язково)

```python
SOURCES = [
    ...
    ("XXXX", "https://новий-постачальник.com/feed.xml"),
]
```

- `"XXXX"` — унікальний числовий префікс для категорій (наприклад `"6666"`)
- Якщо не потрібен префікс категорій — поставити `""`

### 2. OFFER_ID_PREFIXES (якщо потрібен префікс offer ID)

```python
OFFER_ID_PREFIXES = {
    ...
    "новий-постачальник.com": "XXXX",
}
```

- Ключ — домен без `https://` і без шляху
- Значення — рядок-префікс (зазвичай той самий що і для категорій)
- Якщо не додати — offer ID будуть без префікса (ризик дублікатів з іншими постачальниками)

### 3. CUSTOM_MARKUP (якщо потрібна індивідуальна націнка)

```python
CUSTOM_MARKUP = {
    ...
    "новий-постачальник.com": {
        "markup_percent": 1.20,   # +20%
        "markup_fixed":   50,     # +50 грн
        # "min_price_raw": 100,   # опціонально — мін. ціна від постачальника
    },
}
```

Якщо не додати — застосовується глобальна `MARKUP_PERCENT` і `MARKUP_FIXED`.

### Приклад: додаємо нового постачальника "newshop.ua"

```python
# 1. SOURCES
("6666", "https://newshop.ua/export/prom.xml"),

# 2. OFFER_ID_PREFIXES
"newshop.ua": "6666",

# 3. CUSTOM_MARKUP
"newshop.ua": {
    "markup_percent": 1.10,
    "markup_fixed":   25,
},
```

## Як видалити постачальника

> ⚠️ **Важливо:** після видалення всі товари цього постачальника зникнуть з прайсу **на наступному запуску** (через 4 години або після ручного запуску). EVA автоматично приберає їх з каталогу.

### Що треба видалити (3 місця)

Відкрийте `masterevaxml.py` і видаліть рядки в кожному з трьох словників:

#### 1. Видаліть рядок з SOURCES

```python
# Знайдіть і видаліть рядок з URL постачальника:
("7777", "https://posudograd.ua/dropship/19155/prom"),   # ← видалити цей рядок
```

#### 2. Видаліть з OFFER_ID_PREFIXES (якщо є)

```python
OFFER_ID_PREFIXES = {
    ...
    "posudograd.ua": "7777",   # ← видалити
    ...
}
```

#### 3. Видаліть з CUSTOM_MARKUP (якщо є)

```python
CUSTOM_MARKUP = {
    ...
    "posudograd.ua": {         # ← видалити весь цей блок
        "markup_percent": 1.0,
        "markup_fixed":   30,
        "min_price_raw":  70,
    },
    ...
}
```

### Практичний приклад — видалення posudograd.ua

**До:**
```python
SOURCES = [

    ("99",   "https://www.websklad.biz.ua/..."),

    ...
    "posudograd.ua": "7777",   # ← є
    "i-posud.com.ua": "8888",

    ...

        "markup_percent": 1.0,
        "markup_fixed":   30,
        "min_price_raw":  70,
    },
    ...
```

**Після:**
```python
SOURCES = [

    ...

    ("8888", "https://i-posud.com.ua/..."),
    ("99",   "https://www.websklad.biz.ua/..."),

    ...
    # posudograd.ua видалено
    "i-posud.com.ua": "8888",
    ...
}

CUSTOM_MARKUP = {
    ...
    # posudograd.ua видалено
    ...
}
```

### Що відбудеться після видалення

1. При наступному запуску скрипт просто **не завантажує** фід цього постачальника
2. Категорії постачальника не з'являться у фінальному XML (там не буде товарів що на них посилаються → категорії видаляться автоматично)
3. Всі offer ID з префіксом `7777_` зникнуть з прайсу
4. EVA при наступному оновленні приберe ці товари з каталогу
5. Префікс `7777` можна **повторно використати** для нового постачальника в майбутньому — але лише якщо старий постачальник більше не повернеться

> **Порада:** якщо постачальник тимчасово недоступний (технічна проблема) — **не видаляйте** його з конфігурації. Скрипт зробить 3 спроби і пропустить цей запуск. На наступному запуску (через 4 год) знову спробує.

### Чи безпечно залишити зайві записи в OFFER_ID_PREFIXES або CUSTOM_MARKUP?

| Сценарій | Що станеться |
|---|---|
| Видалили з `SOURCES`, але залишили в `OFFER_ID_PREFIXES` | Нічого — цей домен просто ніколи не зустрінеться |
| Видалили з `SOURCES`, але залишили в `CUSTOM_MARKUP` | Нічого — налаштування просто не застосується |
| Забули видалити з `SOURCES` | Скрипт спробує завантажити фід і, якщо URL недоступний, пропустить після 3 спроб |

## Blacklist — блокування окремих товарів

Створіть файл `blacklist.txt` у корені репозиторію. Один offer ID на рядок. Рядки що починаються з `#` — коментарі.

```
# Товари що не повинні бути в прайсі
1111_ABC123
2222_XYZ456
# Тимчасово прибрали
3333_DEF789
```

**Де взяти offer ID:** він видно в `REPORT.md` у секції дублікатів, або в `price_warnings.log`.

Якщо `blacklist.txt` відсутній — скрипт продовжує без нього (не ламається).

## Звіт REPORT.md

Після кожного запуску GitHub Actions оновлює файл `REPORT.md` з двома таблицями:

### Таблиця 1 — Результати по постачальниках

| Колонка | Що означає |
|---|---|
| ✅ OK | Товарів додано до прайсу |
| 💰 Низька ціна | Відфільтровано через мінімальну ціну |
| 🚫 Недоступні | `available=false` або відсутнє фото |
| ⚠️ Помилки ціни | Не вдалось розпарсити ціну або інші помилки |
| 📦 Сток за замовч. | Постачальник не вказав кількість → DEFAULT_QTY=2 |
| 🔁 Дублі | Offer ID збігся з іншим постачальником |
| 🚷 Blacklist | Виключено через blacklist.txt |

### Таблиця 2 — Якість даних

| Колонка | Що означає |
|---|---|
| 🇺🇦 Назва UA | Назва з тегу `name_ua` або з UA-символами |
| 🇷🇺 Назва RU | Назва тільки в тегу `name` з RU-символами |
| 🇺🇦 Опис UA | Опис з тегу `description_ua` або з UA-символами |
| 🇷🇺 Опис RU | Опис тільки в тегу `description` з RU-символами |
| ❌ Без опису | Постачальник не надав опис |
| 📸 2+ фото | Товарів з двома і більше фотографіями |
| ⚙️ Без парамів | Параметри відсутні → підставлено базові |
| 🏷️ Без артикула | Немає vendorCode / article |
| 💰 Ціна min–max | Діапазон кінцевих цін у прайсі |

### Статуси

- 🟢 **ОК** — всі постачальники завантажились, попереджень немає
- 🟡 **УВАГА** — є попередження по цінах або дублікати
- 🔴 **КРИТИЧНО** — один або більше постачальників не завантажились

## Troubleshooting

### Постачальник показує 0 товарів

1. Перевірте `REPORT.md` — колонку **⚠️ Помилки ціни** і **🚫 Недоступні**
2. Відкрийте `price_warnings.log` — там детальні помилки
3. Перевірте чи URL фіду ще доступний (відкрийте в браузері)
4. Перевірте чи не змінилась структура XML фіду

### Постачальник зник з прайсу після запуску

Можливі причини:
- Фід тимчасово не відповідав (3 спроби не дали результату)
- URL змінився
- Постачальник заблокував User-Agent скрипту

Рішення: зачекайте наступний запуск (4 год) або запустіть вручну через **"Run workflow"**.

### Категорії постачальника зникли

Якщо в категорії залишилось ≤ `MIN_OFFERS_PER_CATEGORY` (3) товарів після фільтрації — вона видаляється автоматично. Змініть `MIN_OFFERS_PER_CATEGORY = 1` якщо потрібно зберігати категорії з 1-2 товарами.

### GitHub Actions перевищує ліміт хвилин

GitHub безкоштовний план: 2000 хв/місяць. При 9 постачальниках і запуску кожні 4 год:
- ~180 запусків/місяць × ~15 хв = ~2700 хв — перевищує ліміт.
- **Рішення:** використовуйте платний план GitHub або зменшіть частоту в `mastereva.yml`:
  ```yaml
  cron: '0 */6 * * *'   # кожні 6 годин (120 запусків/місяць)
  ```

### Прайс не оновлюється на EVA

EVA кешує прайс. Зміни відображаються з затримкою до 1 години після того як файл оновився на GitHub Pages. Перевірте дату оновлення в `REPORT.md`.

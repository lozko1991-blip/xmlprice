# SYSTEM REQUIREMENTS & AI GUIDELINES FOR MASTEREVA XML PROJECT

Цей файл є "конституцією" проєкту. Будь-який AI-асистент, який працює з цим кодом, **ЗОБОВ'ЯЗАНИЙ** спочатку прочитати та дотримуватися цих правил, щоб уникнути галюцинацій та не зламати крихку логіку XML-парсерів, ціноутворення та усунення дублікатів.

## 1. Архітектура та Головні Файли
- **`masterevaxml.py`**: Головний скрипт, який збирає всі XML-фіди від різних постачальників, приводить їх до єдиного формату, перекладає категорії українською, застосовує націнки та формує фінальний XML для платформи Prom/EVA.
- **`markup_config.py`**: Файл конфігурації націнок (tiered markup, percent, fixed, min_profit, overrides). 
- **`content_overrides.py`**: Файл для ручного перевизначення назв та описів товарів (за ID).
- **`blacklist.txt`**: Гнучкий файл чорного списку (категорії, постачальники, слова, конкретні ID товарів). Підтримує прив'язку до домену.

## 2. Обробка XML (Критично важливо!)
- **Парсинг:** Використовувати **ТІЛЬКИ `lxml.etree`**. Ніколи не використовувати регулярні вирази для парсингу або модифікації XML-структури. Файли постачальників можуть бути невалідними, тому під час читання завжди використовується `ET.XMLParser(recover=True)`.
- **CDATA:** Текстові вузли (назви, описи) обов'язково повинні обгортатись у `<![CDATA[...]]>`, якщо вони містять HTML або спеціальні символи. В `lxml` це робиться через `element.text = ET.CDATA(текст)`. Ніколи не намагайтеся зробити це через строкові заміни після генерації XML.
- **Енкодінг:** Фінальний XML має бути у кодуванні `utf-8` з відповідною декларацією.

## 3. Управління ID товарів та категорій
- **Префікси:** Оскільки у різних постачальників можуть збігатися ID товарів або категорій, кожному постачальнику жорстко призначено префікс (наприклад, `"1000"`, `"2000"`). 
  - Формат фінального ID товару: `ПРЕФІКС_ОригінальнийID` (наприклад, `2000_12345`).
  - Формат фінального ID категорії: `ПРЕФІКС + ОригінальнийID` (наприклад, `200014975`).
- **Заборона змін:** Ніколи не змінюйте логіку додавання префіксів без явного дозволу, інакше ви зруйнуєте прив'язку товарів до категорій.

## 4. Захист від дублікатів (Single Item Retention)
- Якщо у постачальника (в одному фіді або між його різними фідами з однаковим префіксом) є кілька товарів з однаковим `offer_id`, скрипт має **залишити рівно один** (перший знайдений), а всі інші — видалити. **Не можна видаляти всі копії повністю**, інакше товар зникне з наявності. Це реалізовано через `seen_offer_ids = set()`.

## 5. Ціноутворення та Націнки
- Усі націнки зберігаються у `markup_config.py`.
- Логіка `get_markup()` враховує:
  1. Індивідуальні націнки на конкретні товари (`item_overrides`).
  2. Тієрні націнки (залежно від вхідної ціни в UAH).
  3. Перевірку мінімального прибутку (`min_profit_uah`).
- Якщо постачальник передає ціну не в гривнях, вона спочатку конвертується в гривні за курсом НБУ або резервним курсом, і тільки потім до неї застосовується націнка.

## 6. Blacklist (Чорний список)
- Файл `blacklist.txt` поділено на секції (`[DISABLED_SUPPLIERS]`, `[DISABLED_CATEGORIES]`, `[DISABLED_KEYWORDS]`, `[STOP_ITEMS]`).
- Він підтримує правила як з двокрапкою (`домен: значення`), так і через пробіл (`домен значення`).
- При зміні парсера `blacklist.txt` потрібно впевнитись, що він коректно обробляє старі записи.

## 7. Робочий процес та Безпека
- Скрипт працює на **GitHub Actions**. Будь-які зміни в код мають бути безперебійними. Якщо виникає помилка, скрипт не згенерує `master_eva.xml`, що зупинить оновлення цін на магазині.
- Перед комітом змін у `masterevaxml.py` або інші важливі файли, обов'язково треба запускати наявні тести, щоб впевнитись, що логіка дублів, націнок та XML не зламана.
